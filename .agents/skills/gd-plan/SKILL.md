# Plan the game

Read `.gd-blueprint/PROJECT.md` and `.gd-blueprint/TASK.md`. Work only in `PROJECT.md`.

- Turn the developer's intent into a clear player promise and repeatable player loop.
- Keep the release small, separate included work from exclusions, and make quality targets observable.
- Order the roadmap by playable value, risk, and dependencies.
- When the Unity snapshot is missing or stale, inspect the editor version, packages,
  render and input setup, main scenes, assemblies, and usable test or build routes.
- Record observed facts and decisions; keep unknowns visible instead of guessing.

Planning updates documentation only. Do not silently change assumptions used by an
unfinished task, create a task, or edit the Unity project.
